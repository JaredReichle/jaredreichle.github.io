About

I build software solutions for teams that test complex systems with real hardware. A lot of that work starts with messy manual steps and ends with repeatable automation people can trust.

Recent projects include reusable API tooling that removed repetitive integration work for multiple internal teams plus automation systems for high-volume signal processing across distributed services. The goal is simple: faster feedback, fewer surprises, and better decisions.

I'm finishing an M.S. in Computer Science with an AI focus and applying that work to test engineering problems. I care most about practical wins like catching patterns early, improving test design, and reducing rework before it hits teams downstream.

I started in electrical engineering. Then I wrote small scripts to remove repetitive lab work. One script became five. Five became tools people used every day. At that point the path was obvious. I enjoyed building software more than drawing schematics.

That hardware background still pays rent every day. When a test rig goes sideways, I don't just stare at logs. I trace signals, question assumptions, and compare device behavior with code expectations. If you've chased a bug across three systems, you know blame can bounce around. This background helps me cut through that noise.

Now I'm finishing an M.S. in Computer Science with an AI focus. However, I care less about hype and more about useful results. For example, I apply machine learning ideas to spot weak tests sooner and surface trends people miss in long runs. The aim is simple: better tests, earlier answers, and fewer late-stage surprises.
